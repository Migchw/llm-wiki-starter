# คู่มือการใช้งาน

วอลต์นี้มีสองส่วนที่อ่านไฟล์ชุดเดียวกัน ส่วนแรกคือ **Obsidian vault** ที่เก็บหลักฐานและโน้ตวิจัยเป็น Markdown ส่วนที่สองคือ **Dashboard** ในโฟลเดอร์ `dashboard/` เป็นเว็บในเครื่องที่แสดงโน้ตคู่กับกราฟราคา graph view และการ์ดผลประกอบการ ปรับหน้าตาเองได้ ทั้งสองส่วนอยู่ใน repo เดียวกัน clone ครั้งเดียวได้ครบ

งานเขียนและตรวจโน้ตทำผ่าน Claude Code ด้วยคำสั่งที่ขึ้นต้นด้วย `/` ส่วน Python script ทำงานที่ตรวจซ้ำได้ เช่น ดึงหน้าเว็บ ตรวจลิงก์ และคำนวณตัวเลข เพื่อให้ AI ใช้แรงกับงานที่ต้องอ่านและตัดสินจริงๆ

[ผังของทุกคำสั่ง](workflows.md#ผัง-swimlane-ของทุกคำสั่ง) · [README](../README.md)

## ตั้งค่าครั้งแรก

1. กด **Use this template → Create a new repository** บน GitHub ตั้งเป็น **Private** เพราะไฟล์ที่ capture มา (filing, transcript) และความเห็นการลงทุนของคุณจะอยู่ใน repo นี้
2. clone repo ของคุณ แล้วติดตั้ง Python 3.10+ ตาม README หัวข้อ "เตรียม Python"
3. เปิดโฟลเดอร์ใน Obsidian (**Open folder as vault**) และรัน `claude` ใน terminal ที่โฟลเดอร์เดียวกัน
4. ถ้าจะใช้ dashboard ติดตั้ง Node.js 22.13 ขึ้นไป แล้วรัน `cd dashboard && npm install && npm run dev` เปิด <http://localhost:3000>
5. พิมพ์ `/onboarding` ใน Claude Code ถ้าอยากให้พาลองแหล่งข้อมูลแรกทีละขั้น

หลังนำเข้าโน้ตใหม่ ถ้า dashboard เปิดอยู่ ให้รัน `npm run index` ใน `dashboard/` แล้ว refresh

## Agent: ใครทำอะไร และทำไมต้องแยก

Munger คือ session หลักที่คุณคุยด้วย ส่วน sub-agent ทั้ง 6 ตัวถูกเรียกเมื่องานต้องการคนแยก ไม่ต้องเรียกเอง

sub-agent เริ่มทำงานโดยไม่เห็นบทสนทนาก่อนหน้า จึงไม่ติดความเห็นที่คุยกันมา เหมาะกับงานตรวจ แต่ยังอ่านวอลต์ชุดเดียวกัน ถ้าวอลต์มีแต่ข่าวด้านเดียว ผลก็ยังเอียงตามนั้น

| Agent | งาน | เครื่องมือ |
|---|---|---|
| Peter Lynch | หาแหล่งข้อมูล ตรวจว่าลิงก์เปิดได้ จัดลำดับเข้า Inbox | ทั้งหมด |
| Ingest Runner | ทำ `/ingest` หนึ่งแหล่งเมื่อ `/research` มีหลายแหล่ง | อ่าน/เขียนไฟล์และรันสคริปต์ เรียก agent ต่อไม่ได้ |
| Feynman | ตรวจตัวเลข วันที่ งวด และ quote เทียบต้นทาง | **อ่านอย่างเดียว** + เปิดเว็บ คืนตาราง Verification ให้ Munger แก้ |
| Reviewer | ตรวจเหตุผล bear case และ moat ที่ไม่มีหลักฐาน | **อ่านอย่างเดียว** คืนข้อเสนอให้ผู้เขียนแก้ |
| Darwin | สกัด Concept ที่ใช้ซ้ำได้ | ทั้งหมด |
| Leopold | ร่าง thesis จากโน้ตที่ผ่านการตรวจ | ทั้งหมด |

คนตรวจแก้ไฟล์ไม่ได้ ทำให้ทุกการเปลี่ยนในโน้ตมีคนเขียนที่ชัดเจน ข้อจำกัดคือ Claude Code จำกัดได้ระดับเครื่องมือ ไม่ได้ระดับโฟลเดอร์ ขอบเขตโฟลเดอร์ของ Ingest Runner จึงยังเป็นคำสั่งในไฟล์ agent

งานที่ต้องรู้ว่าคุณอยากสื่ออะไร เช่น เขียนบทความ ควรทำใน session หลัก เพราะ sub-agent ไม่เห็นบทสนทนา

## ปรับแต่ง Dashboard

| อยากเปลี่ยน | แก้ที่ |
|---|---|
| หุ้นที่ติดตาม | `dashboard/config/watchlist.json` (`entity` ต้องตรงกับชื่อไฟล์ใน `02-Wiki/Entities/`) |
| สี ฟอนต์ ธีมสว่าง/มืด | ตัวแปร CSS ใน `dashboard/app/globals.css` |
| การ์ดและหน้าต่างๆ | `dashboard/components/` และ `dashboard/app/` |

Dashboard อ่านวอลต์อย่างเดียว ข้อมูลที่มันสร้าง (`data/wiki-index.json`, ราคา, earnings) ถูก `.gitignore` ไว้และสร้างใหม่ได้เสมอ ถ้าไม่มีเน็ตหรือ Python ส่วนนั้นจะว่างแต่หน้าเว็บยังเปิดได้

## ดูแลตัวระบบ

- **แก้ agent หรือ skill ที่ `.agents/` เท่านั้น** แล้วรัน `python scripts/wiki_tool.py --sync-agents` เพื่อ copy ไป `.claude/` ที่ Claude Code อ่าน ถ้าลืม `--lint` จะบอกไฟล์ที่ไม่ตรงกัน
- **ตรวจวอลต์:** `python scripts/wiki_tool.py --lint` ตรวจลิงก์ frontmatter และความตรงกันของ `.agents/` กับ `.claude/`
- **ทดสอบ fetcher:** `python -m unittest discover -s tests` ยืนยันว่า capture ซ้ำไม่เขียนทับ Raw เดิม
- **แก้ผัง:** แก้ spec ใน `docs/diagrams/flows.py` แล้วรัน `python docs/diagrams/build_flows.py`
- **แก้โค้ด:** skill `karpathy-guidelines` ใช้กับงานใน `scripts/` และ `dashboard/` ให้แก้เท่าที่จำเป็นและตั้งเกณฑ์ตรวจผลก่อนลงมือ

## ใช้หลายเครื่อง

ก่อนเริ่มงานทุกครั้ง agent จะรัน `git fetch` อ่าน commit ล่าสุด แล้ว `git pull --rebase` ตาม `.agents/AGENTS.md` ถ้ามีไฟล์ค้างหรือ conflict จะหยุดถามก่อน จบงานแล้ว agent จะ commit และบอกว่ามีอะไรรอ push คุณเป็นคนสั่ง push เอง

คำสั่ง preflight ใช้ branch ที่ track อยู่ (`@{u}`) จึงใช้ได้ทั้ง repo ที่ใช้ `main` และ `master`

## ให้ ingest ทำงานเองเมื่อมีไฟล์เข้า inbox

agent ใน Claude Code ทำงานเมื่อถูกเรียกเท่านั้น ไม่ได้รันค้างไว้ `scripts/watch_inbox.py` ทำหน้าที่คนเรียกให้ ตั้งให้ Windows Task Scheduler รันทุกชั่วโมง:

```bat
schtasks /Create /SC HOURLY /TN "LLM Wiki inbox" /TR "py \"C:\path\to\vault\scripts\watch_inbox.py\""
```

ลบ task ด้วย `schtasks /Delete /TN "LLM Wiki inbox" /F` ส่วน macOS/Linux ใช้ cron เรียกสคริปต์เดียวกัน

แต่ละรอบทำงานแบบนี้:

1. ถ้า `01-Raw/inbox/` ว่าง จบทันที ไม่เสีย token
2. ถ้ามีงานจากรอบก่อนที่ยังไม่ได้ commit ก็จบทันทีเหมือนกัน รอให้คุณตรวจก่อน ไฟล์ใหม่ใน inbox ไม่นับเป็นงานค้าง
3. ถ้ามีไฟล์ใหม่ จะเรียก `claude -p` ให้ `/ingest` ทีละไฟล์ แล้วย้ายไฟล์ไปโฟลเดอร์ตามประเภท ไฟล์ที่ทำไม่ได้ถูกย้ายไป `01-Raw/inbox/hold/` พร้อมแถว `waiting` ใน Ingest Queue จึงไม่ถูกลองซ้ำ
4. ไม่ commit และไม่ push ผลของแต่ละรอบอยู่ใน `03-Logs/Watch/` คุณอ่าน ตรวจ แล้ว commit เอง รอบถัดไปจึงทำงานต่อ

ลองดูว่าจะทำอะไรโดยไม่รันจริง: `py scripts/watch_inbox.py --dry-run`

รอบที่มีงานเสีย token ตามจำนวนไฟล์ ถ้าไม่อยากให้วิ่งเองก็ไม่ต้องตั้ง task แค่พิมพ์ `/ingest` ตามปกติ

## ข้อควรรู้

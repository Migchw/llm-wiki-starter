ส่วนที่ 1

AI พื้นฐานที่ต้องรู้ก่อน

ก้าวที่ 1 · รู้จัก AI

LLM (แชท AI) คืออะไร แบบง่ายที่สุด

LLM คือโปรแกรมที่ ทายคำถัดไป จากข้อความที่ป้อนให้ — ไม่มีความทรงจำถาวร ไม่ได้ "รู้จัก" เราจริง ๆ

ทุกครั้งที่เปิดแชทใหม่ มันเริ่มจากศูนย์ สิ่งเดียวที่มันเห็นคือข้อความที่อยู่ใน หน้าต่างสนทนาตรงหน้า

สรุปสั้น

AI เก่งเรื่อง "คิดต่อจากสิ่งที่เห็น" ไม่เก่งเรื่อง "จำสิ่งที่ไม่ได้เห็น"

คนใหม่มักเข้าใจผิดว่า AI "จำ" เราได้เหมือนคนคุยกันบ่อยๆ อธิบายว่าความรู้สึกว่ามันจำได้ มาจากการที่แอปแนบประวัติแชทเก่ากลับเข้าไปให้มันอ่านใหม่ทุกครั้ง ไม่ใช่มันจำเองในหัว
ก้าวที่ 2 · Context window

Context window คือ "โต๊ะทำงาน" ของ AI

ข้อความที่เราพิมพ์
+
ไฟล์ที่แนบ
+
ประวัติแชท
=
สิ่งที่ AI มองเห็นได้ ณ วินาทีนั้น

โต๊ะทำงานมีขนาดจำกัด (วัดเป็น token) — วางของเกินโต๊ะ ของที่วางก่อนจะถูกปัดตกออกไป หรือ AI จะเริ่ม "หลงบริบท"

ใช้ analogy โต๊ะทำงาน/กระดานไวท์บอร์ดที่มีพื้นที่จำกัด อธิบาย token คร่าวๆ ว่าประมาณคำ/พยางค์ ไม่ต้องลงลึกคณิตศาสตร์
ก้าวที่ 3 · ปัญหาของการยัดข้อมูลเยอะเกินไป

ทำไม "แปะทุกอย่างลงแชท" ถึงไม่ใช่คำตอบ

ต้นทุนสูง

ยิ่งบริบทยาว ยิ่งใช้ token เยอะ ยิ่งช้าและแพงขึ้นทุกข้อความ

คุณภาพตก

ข้อมูลตรงกลางบริบทยาวๆ มักถูก AI "มองข้าม" ง่ายกว่าหัว-ท้าย

ไม่ยั่งยืน

พอปิดแชท ทุกอย่างหายหมด ต้องแปะใหม่ทุกครั้ง

ตรวจสอบไม่ได้

ไม่มีที่เก็บถาวรให้ย้อนดูว่า AI อ้างอิงอะไรมา

นี่คือจุดเชื่อมไปสู่ RAG และ second brain — บอกว่าปัญหานี้แหละที่ทำให้ทั้งวงการ AI หันมาใช้แนวทาง "ดึงเฉพาะที่จำเป็น" แทนการยัดทุกอย่าง
ก้าวที่ 4 · RAG

RAG คืออะไร แก้ปัญหานั้นยังไง

RAG (Retrieval-Augmented Generation) = ก่อนตอบ ให้ AI "ค้นหา" ข้อมูลที่เกี่ยวข้องจากคลังความรู้ก่อน แล้วค่อยเอามาวางในบริบทเท่าที่จำเป็น

คำถาม
→
ค้นในคลังความรู้
→
ดึงเฉพาะส่วนที่เกี่ยว
→
ใส่ในบริบท แล้วให้ AI ตอบ

แทนที่จะยัดทั้ง vault ทุกครั้ง เราส่งไปแค่ "หน้าที่เกี่ยวข้อง" — ประหยัด token และแม่นยำขึ้น

RAG คือเหตุผลเชิงเทคนิคว่าทำไม vault ที่จัดระเบียบดี (มี index, มี link) ถึงทำให้ AI ค้นเจอของถูกต้องเร็วกว่าโฟลเดอร์ไฟล์กองรวมกัน
ก้าวที่ 5 · ศัพท์ที่มักปนกัน

แยกศัพท์ให้ชัดก่อนไปต่อ

คำอยู่หมวดไหน
LLM Wiki / Second Brainเป้าหมาย — สิ่งที่เราอยากได้
Knowledge Graphโครงสร้างข้อมูล — โหนดกับเส้นเชื่อมระหว่างความรู้
RAGสถาปัตยกรรม AI — วิธีที่ AI ดึงข้อมูลมาใช้
Obsidian, Graphifyเครื่องมือ — โปรแกรมที่หยิบมาใช้ได้จริง

วันนี้เราไม่ได้สร้าง Knowledge Graph ด้วยมือ — เราสร้าง Wiki ที่มี link แล้ว Obsidian วาดกราฟให้เองจากลิงก์นั้น

คนใหม่มักงงว่า RAG กับ Knowledge Graph คือของเดียวกันไหม ย้ำว่าคนละชั้น: หนึ่งคือเป้าหมาย หนึ่งคือกลไก หนึ่งคือสถาปัตยกรรม หนึ่งคือเครื่องมือ

แนวคิด Second Brain

ก้าวที่ 6 · Second Brain

Second Brain คืออะไร?

ไม่ใช่ "สมองสำรองที่จำทุกอย่างแทนเรา" — แต่เป็นระบบภายนอกที่ช่วยเรา:

เก็บหลักฐานที่หาใหม่ได้ยาก

เห็นความสัมพันธ์ข้ามเวลา / ข้ามบริษัท

ทบทวนว่าเราเคยคิดอะไร เพราะอะไร

ส่ง context ที่เชื่อถือได้ให้ AI ช่วยคิดต่อ

เป้าหมายคือคิดดีขึ้นและตรวจสอบได้ ไม่ใช่สะสมโน้ตให้เยอะที่สุด

เตือนไม่ให้ผู้ฟังตกหลุม "สะสมโน้ต" — จุดสำคัญคือทุกโน้ตต้องมีทางย้อนกลับไปหลักฐาน ไม่ใช่จำนวนไฟล์
ก้าวที่ 7 · ทำไม Markdown + Obsidian

ทำไมไม่ใช้ Notion, Word หรือแชท AI เก็บแทน

Plain text (Markdown)

อยู่ได้นาน ย้ายแอป/ย้ายเครื่องได้ เก็บด้วย Git หรือ OneDrive ได้ ไม่ผูกกับผู้ให้บริการรายเดียว

Obsidian

ทำงาน local-first บนเครื่องเรา มี search, properties, backlinks และ graph โดยไม่ต้องพึ่งเซิร์ฟเวอร์ใคร

---
type: concept
tags: [investing]
---
# Free cash flow
ดูต่อ: [[Capital cycle]]
ข้อเสีย: ต้องมีวินัยในการจัดระเบียบเอง และถ้าใส่ plugin/graph เยอะเกินไป ระบบจะซับซ้อนโดยไม่จำเป็น
ถ้ามีคนถามว่า "ทำไมไม่ให้ AI จำเอง" ให้ย้อนกลับไปสไลด์ context window — AI ไม่มีที่เก็บถาวรของตัวเอง เราต้องเป็นคนสร้างที่เก็บให้มัน

ก้าวที่ 14 · Quality gate

งานลงทุนต้องผ่านเกณฑ์อะไรก่อนเชื่อได้

แยก 3 อย่างเสมอ

Fact, interpretation, และ open question ต้องไม่ปนกันในไฟล์เดียว

ตรวจ primary source

ตัวเลข/filing/earnings ที่กระทบ thesis ต้องเช็กกับต้นฉบับ

มีด้านค้าน

ทุก thesis ต้องมี contrary case, ความเสี่ยง และวันที่นัดทบทวน

ย้อนกลับได้

ทุก concept/thesis ต้องลิงก์กลับไป source note และ Raw ได้เสมอ

LLM Wiki ช่วยคิดและช่วยตรวจสอบย้อนกลับ — ไม่ใช่คำแนะนำการลงทุน และไม่รับประกันผลตอบแทน

สไลด์นี้สำคัญมากสำหรับ audience นักลงทุน ให้พูดช้าๆ นี่คือจุดที่ทำให้ vault นี้ต่างจากการถามแชท AI ทั่วไปแล้วเชื่อคำตอบทันที

ก้าวที่ 16 · คุยกับ AI ให้ได้ผลลัพธ์ดีขึ้น

Prompt patterns ที่ใช้ได้จริงใน vault นี้

Ingest

"อ่าน AGENTS.md จัดไฟล์นี้เข้า Raw ที่ถูกต้อง เติม frontmatter ตาม template ยังไม่ตีความเนื้อหา"

Research

"จาก [[raw-x]] สร้าง source note ตาม template ทุก fact ระบุตำแหน่งหลักฐาน แยก interpretation/question"

Critic

"ตรวจ [[thesis-x]]: หา 3 ข้อโต้แย้ง หลักฐานที่หายไป และอะไรจะล้ม thesis อย่าเขียนทับ thesis"

Retrieve

"ใช้เฉพาะโน้ตที่ link จาก [[topic-index]] สรุปพร้อม source links และบอกความไม่แน่นอน"

สูตร: ให้ AI มี บทบาท + ขอบเขต + หลักฐาน + รูปแบบ output — อย่าถามลอยๆ ว่า "สรุปให้หน่อย"

ให้ผู้ฟังลองพิมพ์ prompt หนึ่งอันจริงๆ ระหว่าง session ถ้ามีเวลา จะช่วยให้จำสูตรนี้ได้ดีกว่าฟังเฉยๆ

5 ข้อที่ต้องจำตลอดเวลา

  1. ห้ามแก้ไขไฟล์ใน 01-Raw/ — ถ้าต้องการตีความใหม่ ให้สร้าง/แก้ใน 02-Wiki/
  2. ห้ามสร้างตัวเลขหรือ fact ลอยๆ — ต้องตรวจย้อนกลับหา Raw ได้เสมอ
  3. เชื่อมโยงลิงก์เสมอ — Source note ลิงก์หา Raw, Concept ลิงก์หา Source note
  4. แยก Fact กับ Interpretation ให้ชัดใน claim table เสมอ
  5. ไม่ให้คำแนะนำเฉพาะบุคคล — ระบุความเสี่ยงและความไม่แน่นอนเสมอ
